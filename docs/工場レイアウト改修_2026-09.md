## 2. 左右にグレーが出る理由（実測済み）

SVGの中身は横いっぱい（x=0〜824）を使っていて、**中に余白は無い**。

```
.factory-svg-wrap svg{ width:100%; max-height:calc(100vh - 115px); }
```

**高さで頭打ちにしている**ため、横に広く縦が短い画面では高さが先に上限へ当たり、
絵が縮んだぶん左右に地色が残る（`preserveAspectRatio` の既定は中央寄せ）。
→ **中身を横に広げる／縦を詰める**と、絵が大きくなって余白も減る。

## 4. 高さが足りない（ここが一番の制約）

カードに入れたい項目（社長の指定）

```
A2  CT 90%                      稼働中     ← 達成率はライン名のすぐ右、状況は右端（2026-09-21 社長指示）
6MA-ステイ-E   11:16〜16:52                ← 加工中の品番と、その予定時間
▓▓▓▓▓▓▓░░░░░░░░░░
見込 18:44 ▼112分     ⚠ 未報告 65分
次: 18326-HL4M-A 17:42〜19:06
```
見出しの並びは `ライン名 → CT達成率 → （空き） → 稼働状況`。
達成率は品番ではなく**ラインの値**なので、ライン名のそばに置く。

5行必要。いまのカードは A/B が高さ82、**C が62**。
C を92まで高くすると、プレスD → 溶接 → 凡例 が順に下がり、**446に収まらない**。

**とる案（おすすめ）**
> 横に広がったぶんを使い、**見込みと未報告を同じ行に並べて 5行に収める**。
> 高さは A/B=82のまま、**C だけ 62 → 88**（プレスCの箱を 160 → 190、プレスD以下を30下げ、
> 溶接・組立SPを 94 → 64、凡例・技術を 68 → 58 に詰める）。

**とらない案**
> すべてのカードを100に。縦が破綻する。

### 停止と再開

実績入力に **「■ 停止する（トラブル記録）」「▶ 再開する」** を足した。
- 停止する … 右上と同じトラブル・停止記録がそのラインで開く（開始時刻はいま）
- 再開する … 終わっていない記録すべてに終了時刻（いま）が入る → 稼働状況は自動で稼働中へ
- ボタンの下に「⛔ 停止中：設備トラブル 15:40から 48分」と現状を出す
- **停止中は見込み完了時刻を、止まっている時間分だけ丸ごと後ろへずらす**

稼働状況の「停止中」は、一度も書かれていなかった `line.stopped` ではなく
**終わっていないトラブル記録**で判定するようにした。

### 遅れの出どころ（v2026.09.21-10）

「CT達成率は達成しているのに、見込み完了が遅い」の理由がその場で分かるように、
**進捗ボードのCT達成率と見込み完了時刻の間に「ロスタイム」**を挟んだ。

```
[ CT達成率 107% ]  [ ロスタイム +93分        ]  [ 見込み完了 19:57      ]
                    段取超過 +63分　停止 +30分     計画 19:06 ／ +51分遅れ
```

| | 出し方 |
|---|---|
| 段取超過 | **行ごとに出している「🔧 段取 ○分／標準○分」の、超えた分の合計** |
| 停止 | トラブル・停止記録の合計（続いているものは今まで） |

★**行の表示とまったく同じ出し方にする**こと（2026-09-21 社長指摘で修正）。
最初は「前の品番の実績の終了が入っている行だけ・1本目は除く」という独自の数え方をしたため、
Bラインが行を見れば +32分（30/26・40/26・40/26）なのに **+14分** と出ていた。
段取り実績の入力があればその値、無ければ推定（`calcImpliedSetup`）。1本目も数える
（行の表示と同じく始業08:10からの推定）。**画面の行を足せばそのまま合う**ことが、
社長が値を確かめる唯一の手がかりなので、ここは絶対にずらさない。

どの行で超えたかも添える … `段取超過 +32分（1行目 +4分・2行目 +14分・3行目 +14分）`

#### 1行の「段取り時間」の決め方（優先順・2026-09-21 社長指示）

1. **段取り時間の実績（`setupActualMin`）**が入っていれば、それ
2. **段取り開始**が入っていれば、そこが始まり。終わりは **段取り終了 → 無ければ 生産開始**
   （休憩は除く。段取り終了も生産開始も無い＝まだ段取り中なので 0）
3. どちらも無ければ推定 … 前の品番の終了 → 生産開始。**1本目は始業 08:10 から**

★2の段は社長の指示で足した。**1本目は前の作業が無いので、段取り開始の入力が唯一のよりどころ。**
3の「始業08:10から」は、段取り開始が入っていないときだけの保険。
段取りがある1本目は段取り開始を入れる運用なので、通常は2で決まる。

検算（`calcLineLoss` を合成データで）：
開始13:00＋終了14:30 → 90分／開始13:00＋生産開始14:30 → 90分／開始だけ → 0分／
11:50→13:30（12:10-12:50の休憩をまたぐ）→ 60分／段取りなし → 0分。

工場レイアウトのカードは5行目に `⏱ 段取+63 停止+30` として出す（次の品番と同じ行）。

### 左右のグレーの余白（v2026.09.21-10）

高さで頭打ちになると、svgの箱は横いっぱいのまま**中身だけ縮んで**左右に地色が残っていた。

```css
/* 前 */ .factory-svg-wrap{flex:1}  svg{width:100%;max-height:calc(100vh - 115px)}
/* 後 */ .factory-svg-wrap{flex:0 1 calc((100vh - 115px) * 1.848)}
         .person-panel{flex:1 1 245px;max-width:720px}
```

箱の幅を「その高さで描ける幅」（= 高さ × 824/446）に決め、余ったぶんは担当者パネルへ回す。

**プルダウンをやめ、送る中身そのものから `lineAutoStatus()` で決める。**
画面には結果だけ「稼働状況（自動）● 段取り中」と出す。

### ロス記録（v2026.09.21-13）

前日のロスの中身を翌日見たい／3か月ためて品番ごとに問題点を検討したい（社長指示）。
進捗管理に **「📉 ロス記録」タブ**を足した。

- 置き場所 … `/lossHistory/<YYYY-MM-DD>/<ラインID>`。**進捗ボードの日次リセットの影響を受けない**
  （`/troubleHistory` と同じ考え方）。約100日で自動削除。
- 残すタイミング … **実績入力のたび／トラブルを入れたり終わらせたりするたび**に上書き（1日1ライン1件）。
  当日は保存前でも、いまの状態をそのまま画面に出す。
- 中身（品番ごと）… 計画数・実績数・数量達成率・CT達成率・段取（実績/標準）・段取超過・
  停止（分と種類）・実績時間・計画時間・備考、そして**原因のしるし**。

| 原因のしるし | つく条件 |
|---|---|
| 段取り | 段取超過 > 0 |
| トラブル | その品番を流していた時間帯に重なった停止 > 0 |
| サイクルタイム | CT達成率 < 95% |
| 数量未達 | 作業終了していて 数量達成率 < 95% |

画面は2つ。**日ごと**（既定は前日）と**品番ごと**（既定は3か月・ロスの大きい順）。
ライン絞り込みとCSV出力つき。

★品番ごとの計算は `lossJobRows()` の1か所だけ。ロスタイムの表示もここを通る。
**行の表示・ロスタイム・ロス記録で数字が食い違わないようにするため、計算を増やさないこと。**
