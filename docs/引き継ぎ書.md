## 0. この文書を読んでいる方へ

この文書は、**社内システムを作った深津健介が対応できなくなったとき**に、
社内の別の担当者、または外部のシステム業者が状況を把握して復旧・引き継ぎができるように
書かれたものです。専門知識がない方が読んでも分かるように書いてあります。

**パスワードや認証キーはこの文書には書いてありません。**
それらは別紙（§2）にまとめ、金庫で保管しています。

### まず落ち着いてください

社内システムは全部で15本ほどありますが、
**止まっても会社の生産・出荷は止まりません。** 紙と口頭で業務は回ります。

本当に急いで対応が必要なのは、次の2つだけです。

| 優先 | システム | 止まると何が起きるか | 猶予 |
|---|---|---|---|
| **1** | 基準遵守手当システム | 手当が計算できず**給与支払いに影響** | 給与計算日まで |
| **2** | 品質チェックシート記録 | 品質記録が残らず**客先監査で指摘を受ける** | 数日 |

他のシステム（段取りナビ、進捗ボード、カメラ等）は、**止まったまま数週間放置しても
実害はありません。** 慌てて触らないでください。

### 最初の3ステップ

1. **§2 を見て、アカウントの権限を確保する**（これが最優先。放置すると全部にアクセスできなくなります）
2. **§3 で、いま何が動いているかを把握する**
3. **§6 の業者選定に進む**か、社内で当面の運用（手作業への切り戻し）を決める

## 1. 全体像（ざっくり）

社内システムは、次の3つの場所に分かれて動いています。

```
【インターネット上】
  GitHub Pages ........ 画面（HTML）を配信している場所。無料。
  Firebase ............ データの保管庫（リアルタイム用）。ほぼ無料。
  kintone ............. 業務データベース（金型・品番・保全）。有料。
  Google Apps Script .. 裏側の処理。無料。
  Slack ............... 通知先。

【事務所】
  中継PC（192.168.30.9）... カメラ中継とビーコン受信。常時起動。

【工場内】
  Tapoカメラ 7台、BLEビーコン、ESP32（ショットカウンター）
```

利用者は、社内のPC・タブレットのブラウザから
`https://84stamp1-jpg.github.io/hashimoto-press/` を開いて使っています。

**特別なソフトのインストールは不要**で、ブラウザだけで動きます。

## 2. ⚠️ 最重要：アカウントの所有者確認

**この章が、この文書で一番重要です。**

システムそのものより、**アカウントの権限を失うことのほうが深刻**です。
個人アカウントで契約しているサービスは、本人が対応できなくなると
**会社が永久にアクセスできなくなる**可能性があります。

### 確認・対処が必要な一覧

| サービス | 用途 | 現在の所有者 | 会社が引き継げるか | 対処 |
|---|---|---|---|---|
| GitHub（84stamp1-jpg） | 全画面の配信元 | ⬜ 要記入 | ⬜ | 会社アカウントへ移管 or 共同管理者を追加 |
| Firebase / Google Cloud | データ保管庫 | ⬜ 要記入 | ⬜ | 会社アカウントを「オーナー」に追加 |
| Google Apps Script（各種） | 裏側処理 | ⬜ 要記入 | ⬜ | 共同編集者を追加 |
| Google（総務経理用の別アカウント） | 経理システム | ⬜ 要記入 | ⬜ | ID・パスワードを金庫へ |
| kintone | 業務DB | 会社契約 | ○ | 管理者が誰か確認 |
| Slack | 通知 | 会社契約 | ○ | 管理者が誰か確認 |
| Anthropic（Claude） | 開発・保守の道具 | ⬜ 要記入 | ⬜ | 支払方法と解約可否を確認 |

**やるべきこと（今すぐ）**

1. 上の表の「現在の所有者」を埋める
2. 個人名義のものは、**必ず会社名義のアカウントを共同オーナー／管理者として追加する**
   （移管でなくてよい。「もう1人が入れる状態」にするだけで、リスクはほぼ消えます）
3. 別紙（ID・パスワード一覧）を作り、**金庫に保管**する。この文書には書かない

> **なぜ急ぐか**: 個人のGoogleアカウントは、本人以外が開けません。
> 遺族でも簡単には引き継げず、手続きに数ヶ月かかるか、失敗します。
> その間、Firebaseのデータも、GASの処理も、誰も触れなくなります。

## 3. システム一覧（重要度順）

### ★★★ 止まると実害が出る

#### 基準遵守手当システム
- **何をするもの**: 減点式の手当を計算し、毎月の支給額を出す
- **使う人**: 総務（給与計算）、各リーダー（減点の記録）
- **どこにある**: kintone（App73減点マスタ / App74減点記録 / App75プロセス管理 / App77期限管理）
  ＋ Google Apps Script ＋ Googleスプレッドシート ＋ Excel（月次処理_v3.xlsm）
- **保管場所**: `Z:\全社共有\総務\基準遵守\`（Excel）、コードは本リポジトリ `基準遵守/`
- **止まったときの代替**: kintoneの減点記録を目視集計して手計算する（1〜2日かかるが可能）
- **注意**: 減点マスタのパターン欄が**全角ＡＢＣだと、エラーが出ないまま計算されない**

#### 品質チェックシート記録システム
- **何をするもの**: 品質チェックの記録・写真をデジタル保存する
- **使う人**: 製造、品質管理
- **どこにある**: `hinshitsu_check.html` ＋ Google Apps Script ＋ Googleスプレッドシート
- **止まったときの代替**: 紙のチェックシートに戻す（**記録は必ず残すこと。客先要求事項**）

## 4. お金の話（契約と費用）

| サービス | 概算費用 | 止めるとどうなるか |
|---|---|---|
| kintone | 有料（人数×月額） | 業務DBが消える。**金型・品番・保全の履歴を失う。止める前に必ずエクスポート** |
| Firebase | 無料枠内のはず | 進捗・位置データが消える。業務履歴としての重要度は低い |
| GitHub Pages | 無料 | 全画面が表示されなくなる |
| Google Apps Script | 無料 | 裏側処理が止まる |
| Slack | 有料 or 無料枠 | 通知が来なくなるだけ |
| Anthropic（Claude） | 従量・月額 | 開発と保守の手段が減る。**業務そのものは止まらない** |
| Tapoカメラ | 買い切り | — |

**費用を止める順番（コスト削減が必要になった場合）**
1. Anthropic（開発を止めるだけ。業務影響なし）
2. Firebase（進捗系の履歴を諦める）
3. Slack（連絡手段を他に移す）
4. kintone ← **最後。ここは業務データそのもの。必ずエクスポートしてから**

## 5. よくある故障と対処

### 画面が真っ白／表示されない
- ブラウザの再読み込み（Ctrl+F5）を試す
- 他のPCでも同じか確認 → 全PCで同じなら配信側（GitHub）の問題
- 特定PCだけなら、そのPCのブラウザ・ネットワークの問題

### カメラが映らない
**これが一番よく起きます。** 原因はほぼ「中継PCが再起動した」です。
1. 事務所の中継PC（192.168.30.9）が起動しているか確認
2. `go2rtc` と カメラページ配信サーバー が動いているか確認
3. 手順は `docs/camera_setup_guide.md` を参照
4. **直らなければ放置して構いません。** 生産に影響しません

### 段取りナビで品番が出てこない
- kintone側のデータかAPIトークンの問題。`docs/SYSTEMS.md` の該当項を参照

### 手当の減点が集計されない
- kintone App73の**パターン欄が全角になっていないか**を最初に疑う（§3参照）

## 6. 外部業者に引き継ぐ場合

### 必要なスキル（一般的な web 開発会社なら対応可能）

- HTML / JavaScript（**フレームワーク不使用**。素のJavaScriptなので難易度は低い）
- Firebase Realtime Database
- Google Apps Script
- kintone（カスタマイズ経験があると望ましい）
- Python（バッチ処理の一部）
- Windows PCの管理（中継PC）

**特殊な技術は使っていません。** 1ファイル完結のHTMLで書かれており、
ビルド作業（コンパイル等）も不要です。ファイルを開けばそのまま読めます。
これは意図的にそうしてあります。**引き継ぎやすさを優先した設計です。**

### 業者に渡すもの

1. この文書
2. GitHubリポジトリ `84stamp1-jpg/hashimoto-press` へのアクセス権
3. `docs/SYSTEMS.md`（システム一覧）、`docs/ARCHITECTURE.md`（構成図）
4. §2の別紙（認証情報）※**必要な範囲のみ。全部渡さないこと**

### 依頼の仕方（現実的な選択肢）

| 方針 | 内容 | 目安 |
|---|---|---|
| **A. 保守のみ** | 壊れたら直す。新規開発はしない | 月額または都度精算 |
| **B. 段階的に廃止** | ★★★の2本だけ残し、他は市販サービス・手作業へ戻す | スポット |
| **C. 全面的に作り替え** | 市販の生産管理パッケージへ移行 | 高額。将来性を考えると非推奨 |

**推奨は B です。** 15本を維持する必要はありません。
本当に必要な2本を残し、残りは「止める」判断をするほうが、費用も手間も小さく済みます。

## 7. 将来、事業を終了するときの手順

会社を閉じる際は、次の順で片付けます。**データの持ち出しを最優先**にしてください。

1. **kintoneから全データをエクスポート**（CSV）。金型・品番・保全履歴。**契約解除前に必ず**
2. Googleスプレッドシートの全ファイルをダウンロード（品質記録・手当記録）
3. Firebaseのデータをエクスポート（JSON）。重要度は低い
4. 保存が必要な記録（品質記録・保全記録）は、**法定保存年限を確認**して外付けHDD等へ
5. 各サービスを解約（§4の順で）
6. 中継PC・タブレット等の端末を初期化・廃棄
7. カメラ・ビーコン・ESP32を撤去

> **注意**: 品質記録・製造記録には**客先との取り決めによる保存義務**がある場合があります。
> 解約前に、ユタカ技研との契約書・品質保証協定書を必ず確認してください。
