# 金型ショット数管理・改修履歴表示　検討メモ（2026-09-22）

社長からの依頼。着手前の整理。

1. 品質チェックの「記録する」で入れている生産数を**金型ごとに累計**し、
   メンテ目安（例：10万ショット）に近づいたら表示を出す
2. 品番検索に、**改修の頻度・改修履歴・いま改修に出ているか**を出す

## 1. 調べてわかったこと

### 生産数（品質チェックの記録）
- 品質チェックの「記録する」→ GAS → Googleスプレッドシート。
  1件ごとに **生産日・品番・生産数・工程（プレスB 等）** が入っている。
- **2026-04-20 から 2,074件・231品番**（2026-09-22 時点）。
- **紙の品質チェックシートのショット数と一致する。**
  例 46487-77R00：紙 9/18＝950・9/21＝1,110 ／ 記録 `46487-77R00-PR (W501)` 9/18＝950・9/21＝1,110。

### ★同じ部品が、工程ごとに別の品番で記録されている
| 品番（記録） | 工程 | ショットに数える？ |
|---|---|---|
| `46487-77R00-PR  (W501)` | プレス B | **数える** |
| `46487-77R00-000   (W501)` | 溶接（スポット） | 数えない |

ほかにも `-WE1A`（溶接）、`-BL`、`-PR1A`、`18120-6Y0 -0000`（空白入り）など、付け方が統一されていない。
→ **「どの記録が、どの金型のショットか」は機械的に決められない。対応表が要る。**

### 改修履歴（App6）
- App6 の部品番号は `46487-77R00-PR` の形（プレス品番）。
- 46487-77R00 は **3件**：

  | 2026-09-16 | 2026-09-21 | 品質確認中 | バリ | CAM/PI工程のピアスバリ改修 |
  | 2026-06-09 | 2026-06-09 | 完了 | 耐久性不足 | 上型サブガイドブッシュ割れ交換 ほか |

## 2. 案

### 2-1. 品番検索に改修履歴（すぐできる）
品番検索のカードの下に：
```
🔧 改修履歴（直近1年 2回）            ⚠ いま改修中：9/16依頼 バリ（品質確認中）
 2026-09-16 → 09-21  バリ       CAM/PI工程のピアスバリ改修        品質確認中
 2026-06-09 → 06-09  耐久性不足  上型サブガイドブッシュ割れ交換      完了
 2025-10-14 → 10-17  改善       CAMCUT取付ボルト折損→交換          完了
```
- App6 を品番の頭（`46487-77R00`）で探す
- 「完了」以外の状況なら **改修中** として目立たせる

### 2-2. ショット数（決めていただくことがある）
金型ごとの台帳を持つ：

| 項目 | 例 |
|---|---|
| 金型（プレス品番） | 46487-77R00-PR |
| 数える記録の品番 | `46487-77R00-PR (W501)` |
| 取り数（1ショットで何個） | 1 |
| 定期メンテ数 | 100,000 |
| 基準日・基準の累計 | 2026-09-21 時点 36,914（紙の最新） |

```
いまの累計 ＝ 基準の累計 ＋ 基準日より後の記録の生産数 ÷ 取り数
```
表示（案）
- **記録した直後**の画面：「累計 96,500 ／ 定期メンテ 100,000（残り 3,500）」
- **品番検索**のカード：同じ表示＋あと何ショットか
- 目安の **90%で注意（橙）／100%で要メンテ（赤）**。朝礼で見る画面に「メンテが近い金型」の一覧

## 3. 決まったこと（2026-09-22 社長）

- **工程ごとの品番それぞれで数える**（-PR・-000・-BL・-WE1A…別々）。**溶接ジグも**生産数で管理する
- 取り数：**1ショットで2個以上取れる金型がある** → マスタに取り数を持つ
- 定期メンテをしたら**累計を0に戻す**
- **赤＝残り（目安−累計）が直近3ロットの平均ショット数以下**（100%には行きたくない）／**橙＝90%**
- 目安は kintone「**マスタ_製品・金型**」に持つ（App7 と思われる。工程ごとの品番が別レコードで入っている）
- 表示は **記録直後・品番検索・朝礼** の3か所
- 品番検索に **改修履歴・工程内不良・苦情不適合** の履歴を出す
- 品番検索の **製造条件（ダイハイト・クッションピン等）は使っていないので消す**

## 4. できたもの（v2026.09.22-8 / -9）

### ショット数
```
いまの累計 ＝ ショット基準累計 ＋ ショット基準日より後の品質チェックの記録の生産数 ÷ 取り数
赤 … 残り ≦ 直近3ロットの平均ショット数（ロット＝製造番号）
橙 … 累計 ≧ 目安 × 90%
```
- 品番のそろえ方：末尾の（W501）などを外し、空白をまとめる（中の空白は残す）。
  記録 `46487-77R00-PR  (W501)` ＝ マスタ `46487-77R00-PR`
- 検算（46487-77R00-PR・目安は仮）：直近3ロット 2,745／1,571／3,000 → 平均2,439。
  36,914→正常／90,500→橙／97,600（残り2,400）→赤。取り数2なら生産数の半分。
- 記録直後：品質チェックの保存完了の画面（**通常の「記録する」のみ。一括振り分けは未対応**）
- 朝礼：ロス記録の上に「メンテが近い金型・ジグ」
- 品質チェックの記録が読めなかったときは判定しない（0件として扱うと誤判定になる）

### 履歴（品番検索）
| 欄 | アプリ | 探し方 | 状態 |
|---|---|---|---|
| 🔧 改修履歴 | App6 | **その工程の品番**（ルックアップ_1） | 動いている。完了以外は「いま対応中」 |
| 🧪 工程内不良 | App31 | 製品の品番（頭の2つ） | GASにトークン登録待ち（項目も未確認） |
| 📣 苦情・不適合 | App45 | 製品の品番（ルックアップ_2） | GASにトークン登録待ち |

App6/31/45 は金型管理システムと同じGAS（`?app=番号`）で読む。トークンはGASのスクリプトプロパティ `KT_TOKEN_<番号>`。

## 5. 社長にお願いすること

### A. マスタ_製品・金型（App7）に項目を4つ
| 表示名 | 種類 | **フィールドコード（このとおりに）** |
|---|---|---|
| ショット数目安 | 数値 | `ショット数目安` |
| 取り数 | 数値（初期値 1） | `取り数` |
| ショット基準日 | 日付 | `ショット基準日` |
| ショット基準累計 | 数値 | `ショット基準累計` |

- 最初は紙の品質チェックシートの最新の値：**基準日＝そのシートの最後の生産日／基準累計＝そのときの累計**
- **定期メンテをしたら：基準日＝メンテした日・基準累計＝0**
- 項目を作ったら「アプリを更新」。値の一覧をExcelでもらえればCSVにして渡す

### B. 工程内不良・苦情不適合を出すには
金型管理システムのGASのスクリプトプロパティに `KT_TOKEN_31`・`KT_TOKEN_45`（閲覧のみのトークン）。
登録するかどうかは、GASの見直し（別件）と合わせて社長が判断する。
