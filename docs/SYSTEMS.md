## 稼働中

### 1. 段取りナビ / H-Hubポータル(dantori_navi.html)
- **目的**: 金型段取り時間の短縮。品番検索→標準作業表示、BLEビーコンによる位置追跡
- **兼務**: `<title>` は「H-Hub」。HHubポータル本体を兼ね、2026-06-03に進捗管理タブを統合済み
- **構成**: BLEビーコン(MM-BLEBC5)+ 常時稼働PC(Node.jsスキャナー)→ Firebase → HTML表示。
  品番マスタは kintone App7
- **表示**: 工場レイアウトSVG v11(viewBox="0 0 824 446")
- **設置**: GitHub Pages 単体 + kintoneポータル埋め込み(kintone.api()直接呼び出し版)
- **既知の課題**: ビーコンアイコンの「ac」表示問題(MACアドレスプレフィックス由来)、
  一部PCでPDF直接表示不可(JSONP方式で対応)
- **セキュリティ対応(2026-07-07)**: HTMLにハードコードされていたkintone App7のAPIトークンを除去。
  トークンが必要な機能は設定画面から端末ごとに入力(localStorage保存)。
  旧トークンはkintone側で失効・再発行済み。新トークンはGASプロキシ(段取ナビ)側に設定
- **GAS URL修正(2026-07-07)**: FIXED_CONFIGのgasUrlが品質チェックUIのデプロイ(JSONP非対応)を
  指していたため、kintoneレコードJSONPプロキシ(旧proxyUrlと同一)に修正。
  品質チェックシートを開く処理はqualityGasUrlを使用するよう変更。
  旧gasUrlを保存済みの端末はリロード時に自動移行

### 5.5 暑さ指数(WBGT)表示・記録 ※上記1と6に内蔵
- **目的**: 熱中症対策。計測器(A&D AD-5698B・黒球式)の値を手入力し、作業別の可否を表示・記録する
- **表示先**: **製造現場 → `dantori_navi.html`(工場レイアウトSVG内・旧「金型置場」の枠 x8 y8 w88 h120)。
  枠クリックで詳細パネル(判定表・入力・記録・設定)が開く /
  技術現場 → `mold_repair_plan.html`(ヘッダー下のバー)**。
  各ファイルの `WB_SHOW` で表示する場所を切り替えている
- **31℃以上は基準温度の設定にかかわらず全作業を×にする**(`WB_DANGER` 固定ルール)。
  基準値を高めに設定していても危険域では○が出ないようにするための安全側の措置
- 左「金型置場」の枠は転用済み。同エリアにビーコンは表示されない運用と確認済み(2026-07-19)。
  `AREA_POSITIONS['金型置場']`(25,55)は残置しているため、将来スキャナーを置く場合は座標変更が必要
- **⚠️ 同じ実装が2ファイルに重複している**(シングルファイルHTML方式のため)。
  **仕様変更時は必ず両方を修正すること**。差分は `WB_SHOW` のみ
- **Firebase**: `/wbgt/config`(設定・全システム共有) / `/wbgt/history/{YYYY-MM-DD}/{場所}`(記録)。
  現在値は履歴の最新レコードから導出する(別に持つと記録修正時にズレるため)
- **設定画面から変更可**: 作業項目名・基準温度(通常/暑熱順化なし)・測定場所名・入力者・
  対応の選択肢・「要測定」に切り替わる時間。コードを触らず運用側で変更できる
- **運用**: 2時間ごとに現場リーダーまたは総務が入力。最終測定から既定150分で「要測定」表示に切替
  (古い値の表示は誤った安心を与えるため)。記録には「とった対応」を必ず残す
  (数値だけの記録は、基準超過時に何もしなかった証拠になりうるため)
- **計測器の制約**: データ出力機能なし。黒球の安定に15〜20分かかるため**持ち回りでの測定は不可**。
  測定場所ごとに1台を常設する必要がある

### 10. 月次会レポート自動生成
- **目的**: #月次会チャンネル(C06PJTWQJ15)の投稿からA4 2ページのPDFレポートを生成
- **運用**: リマインダーは毎月5日・10日・14日に自動送信。報告締切は毎月15日。
  締切後にチャット側で「N月の月次報告をまとめて」等を依頼するとPDFを生成する
- **データソース**: #月次会の各部門投稿(品質=八木、製造=見原、組立=永丘、技術=大石/遠藤、
  納入=木村)、深津英介氏添付のプレス実績/全体実績PDF、八木氏添付の苦情品質PDF、
  Z:ドライブの目的目標実施計画.xlsx(社内共有フォルダ)。複数ソースを突き合わせて数値を確認する
- **ツール**: `templates/monthly_report_template.py`(Excel入力→PDF生成)。
  `init`で空の雛形xlsxを新規作成、`build`でxlsxを読みPDFを生成。
  月次データ(xlsx/PDF)は**このリポジトリには置かず**ローカルPC(Desktop等)で管理する
  (GitHub Pagesは公開リポジトリのため。金型改修・人事的な指摘等の内部情報を含む)
- **依存**: `pip install reportlab matplotlib openpyxl pypdf`(pypdfはPDF内容検証用、必須ではない)。
  日本語フォントはWindowsのMeiryo/游ゴシックを自動検出、reportlab内蔵CIDフォントにフォールバック
- **運用フロー**: 前月の完成済みxlsxを当月分としてコピー→上記データソースで各シートを更新→
  buildでPDF生成→内容確認→（必要なら）#月次会へ投稿は都度確認の上で実施
- **注記**: 2026年7月に一度、月次のリマインダーはあるが実際の生成依頼を失念する事故が発生。
  月次会のたびに必ず本項の運用を実施すること
